# PA Governance Radar

A static, zero-backend dashboard visualizing Medicare Advantage
prior-authorization denial-rate variance across 61 insurer contracts.

**➡️ Live site:** enable GitHub Pages (see [Deploying](#deploying) below) and
the URL will be `https://<your-username>.github.io/PA-Governance-Radar/`.

## Real data vs. synthetic data — read this first

This project deliberately mixes exactly two kinds of numbers, and every
place they appear on the site they are labeled which is which:

| | Status | What it is |
|---|---|---|
| Aggregate stats (61 contracts, 1.9%–24.6% denial-rate range, 94.6% appeal-overturn rate) | **Real, cited** | Publicly reported figures, sourced below |
| Every per-contract row (contract ID, state, plan type, exact denial rate, appeal counts) | **Synthetic** | Generated by a seeded RNG (`seed=2026`), calibrated only so the dataset's aggregate min/max/overturn rate matches the real cited figures |

**Why synthetic and not real per-contract data:** Under CMS-0057-F, U.S.
health payers were required to publicly post CY2025 prior-authorization
metrics by March 31, 2026. Centene Corporation's real per-contract breakdown
is scattered across dozens of separately hosted payer disclosure pages. That
breakdown was **not scraped** for this project and is **not fabricated as if
real** anywhere in this repo — instead, `data/generate_dataset.py` produces a
synthetic reconstruction whose only constraint is matching the real, cited
*aggregate* numbers (contract count, denial-rate range, overturn rate).

This project has **no access to, and does not represent, Centene
Corporation's actual internal claims or utilization-management systems.**

### Sources (accessed August 2026)

1. [CMS-0057-F Interoperability and Prior Authorization Final Rule — fact sheet](https://www.cms.gov/newsroom/fact-sheets/cms-interoperability-and-prior-authorization-final-rule-cms-0057-f) — cms.gov
2. ["Prior authorization denials vary widely among insurers"](https://www.healthcaredive.com/news/prior-authorization-denials-vary-widely-among-insurers/827891/) — Healthcare Dive
3. [Medicare Advantage denial rates by insurer](https://www.authdenied.com/insights/medicare-advantage-denial-rates-by-insurer) — AuthDenied (2026 aggregation)
4. ["Using public payor prior-authorization data"](https://www.forvismazars.us/forsights/2026/08/cms-0057-f-using-public-payor-prior-authorization-data) — Forvis Mazars (August 2026)

The real, cited aggregate figures (61 contracts, 1.9%–24.6% denial-rate
range, 94.6% appeal-overturn rate) come from Healthcare Dive's reporting on
Centene's CY2025 CMS-0057-F disclosures, as aggregated by AuthDenied.

## How the dataset is built

```
data/generate_dataset.py   → data/contracts.json      (61 synthetic contract records)
data/compute_stats.py      → site/data/stats.json     (stats + outlier flags + explanations)
```

- **`generate_dataset.py`**: draws 61 denial rates from a seeded
  (`numpy.random.default_rng(2026)`) right-skewed Beta(2,5) distribution,
  rescaled so the sample min/max land exactly on the cited real range
  (1.9%–24.6%). Appeal volumes and per-contract overturn rates are likewise
  seeded, then nudged so the dataset-wide overturn rate is exactly 94.6%,
  matching the cited real aggregate. State and plan type are synthetic
  fields with no real-world correspondence to actual contracts.
- **`compute_stats.py`**: reads `contracts.json`, computes the company-wide
  median denial rate, a per-contract z-score, and flags contracts with
  `|z| > 1.5` as outliers. For each flagged contract it generates a
  one-paragraph explanation using **pure deterministic string templating**
  — no LLM call, no external API:

  > "Contract {id} in {state} denies {rate}% of MA prior-auth requests,
  > {x} points above the Centene-wide median of {median}% — a {z}-sigma
  > outlier within this synthetic reconstruction."

  The output, `site/data/stats.json`, is committed to the repo so the
  deployed site loads instantly with no build step for a visitor.

### Regenerating the dataset

```bash
pip install -r requirements.txt
python3 data/generate_dataset.py
python3 data/compute_stats.py
```

Both scripts are deterministic given the fixed seed — rerunning them
reproduces byte-for-byte the same `contracts.json` and (module the
`generated_at` timestamp) `stats.json`.

## Running the site locally

The site is pure static HTML/CSS/JS with **no build step**:

```bash
cd site
python3 -m http.server 8000
# open http://localhost:8000
```

`site/app.js` fetches the already-committed `data/stats.json` and renders a
[Chart.js](https://www.chartjs.org/) (loaded from cdnjs, no npm install)
bar chart, a sortable table, and the outlier explanation blocks.

## Deploying

This repo ships a GitHub Actions workflow
(`.github/workflows/pages.yml`) that publishes the `site/` directory to
GitHub Pages on every push to `main` — free, no CLI, no paid tier.

Because GitHub Pages' "deploy from branch" mode can only serve the repo
root or a `/docs` folder (not an arbitrary `/site` directory), this repo
uses the standard Actions-based Pages deployment instead, which supports
publishing any folder.

One-time manual step (cannot be done via `git push` alone):

1. Go to **Settings → Pages** in the GitHub repo.
2. Under **Source**, select **GitHub Actions**.
3. Push (or merge) to `main` — the `pages.yml` workflow runs automatically
   and publishes `site/` to `https://<your-username>.github.io/<repo>/`.

No API keys, no paid services, and no server are involved anywhere in this
pipeline.

## Stretch goal (out of scope, not implemented here): a real scraper

The real per-contract CMS-0057-F disclosures are hosted individually by
each of Centene's ~61 reporting contracts on separate payer-controlled
pages, not in one aggregate feed. A future, separate project could:

1. Enumerate Centene's 61 contract-level disclosure page URLs (these
   change over time and are not centrally indexed).
2. Fetch and parse each page's CY2025 PA metrics (format varies by page —
   likely a mix of HTML tables and downloadable files).
3. Replace `generate_dataset.py`'s synthetic-generation logic with this
   real scraper's output, keeping `contracts.json`'s schema
   (`contract_id`, `state`, `plan_type`, `denial_rate`, `appeals_filed`,
   `appeals_overturned`) unchanged so `compute_stats.py` and the site work
   without modification.
4. Update every "SYNTHETIC" label on the site to reflect that the
   per-contract data is now real, and re-verify the aggregate figures still
   match public reporting.

This is **not implemented in this repository** — it is documented here only
as a possible future direction, and the current codebase must not be
represented as doing this scraping.

## Hard constraints this project follows

- No paid API keys anywhere, including the outlier-explanation text, which
  is deterministic string templating, not an LLM call.
- No backend server, no database — a static site plus committed JSON.
- Every synthetic number is visually (orange "SYNTHETIC" badges, outlier
  row highlighting) and textually distinguished from the real cited
  aggregate stats on the page itself.
- No claim of access to Centene's actual internal claims or
  utilization-management systems, anywhere in code, UI copy, or this
  README.
